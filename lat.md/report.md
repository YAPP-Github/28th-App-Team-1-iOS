# report

AI 면접 리포트 Feature(`FeatureReport`)의 도메인 노드. 화면 4개 + 메인 위 바텀시트 1개로 구성한다. 면접 종료 후 채점 결과를 사용자용 리포트로 보여주고, 영상 복기·지인 피드백 요청으로 잇는다. 기획→코드 매핑은 [ai-interview-report](../docs/work/ai-interview-report.md), 서버 계약은 [[api#Interview Report]].

## 코디네이터

`ReportFeature` — 1차 리포트를 루트로 두고 나머지 화면을 `path`(StackState)로 push 한다. 각 화면의 delegate 만 매칭한다(D5). 부모(AppFeature)로 올리는 것은 `retryRequested`(분석 부족 → 다음 면접)·`closeRequested` 둘뿐 — 나머지 전환은 모듈 안에서 끝난다.

**진입은 홈 위젯②의 [레포트 보기]** 다(2026-08-05 배선) — AppFeature 가 세션 id 로 fullScreenCover 를 세우고 두 신호를 받는다 → [[app#Cross-feature Routing]]. 면접 정상 종료에서 곧장 잇는 경로는 아직 없다(면접은 리포트 대기 화면에서 홈으로 돌아간다 — [[interview#코디네이터]]).

**메인이 허브다.** 화면들은 한 줄로 이어지지 않는다: 영상 플레이어는 리포트의 종속 화면이지 지인 피드백의 앞 단계가 아니고, 영상을 보지 않고 바로 지인에게 보낼 수 있어야 한다. 그래서 각 화면 진입은 메인의 개별 delegate(`videoRequested`·`peerFeedbackRequested`)가 트리거한다.

## 1차 리포트

`ReportMainFeature` — 루트이자 상세 화면. 요약 화면을 따로 두지 않는다(이탈 이력). `InterviewReportClient.report` 한 번으로 전 화면 데이터를 받고, `.generating` 이거나 `reportNotFound` 면 폴링한다 — **`reportNotFound`(404)는 에러가 아니라 미생성 상태라서 폴링을 계속한다**.

폴링 상한 초과(`pollTimedOut`)와 재시도 가능 에러는 화면의 «다시 시도하기» 버튼(`userTappedReload`)으로 되살린다 — 카운터를 리셋하고 재조회. 세션 없음·로그인 만료는 다시 눌러도 같은 답이라 버튼을 주지 않는다(정의서 §4-4).

노출 금지: 종합점수·채용 판정·천장·항목 점수·레드플래그 원문. 사용자 문구는 대부분 서버 소유(`headline`·`redFlagNotices.message`·`card.resolutionNotice`)라 클라가 만들지 않는다 — 클라 하드코딩은 영상 카드 문구·안내 줄·nil 폴백·시트 마무리 문구뿐.

**카드는 세로로 늘어놓지 않고 질문 탭으로 한 장씩 본다**(`selectedCardIndex`). 대본이 길어 전부 펼치면 스크롤이 무너진다. 폴링 중 카드 수가 줄면(분석 부족 확정) 선택 위치를 처음으로 되돌린다.

레드플래그 유무는 «상세 리포트» 제목 옆 느낌표로 알리고, 시안(443:7264)대로 문구 툴팁을 **함께** 띄운다(`isRedFlagTooltipVisible` 기본 펼침, 느낌표를 눌러 접는다). 레드플래그가 없으면 느낌표·툴팁 둘 다 그리지 않는다. 툴팁은 오버레이라 열고 닫아도 아래가 밀리지 않는다.

영상 카드의 남은 시청 시간은 State 가 아니라 View 의 `TimelineView` 가 `video.expiresAt` 에서 파생해 1초마다 그린다 — 리듀서에 1초 틱을 넣으면 폴링과 무관한 액션이 매초 흘러 테스트만 시끄러워진다.

**지인 피드백 섹션은 두 얼굴이다.** 아무도 안 남겼으면 «지인에게 보내기» 요청 카드, 한 명이라도 남겼으면 지인 이름 탭 + 그 지인의 태도 평가 목록으로 바뀐다. 요청 카드의 분모(정원)는 서버에 없어 `maxGuestCount` 상수로 둔다.

태도 평가는 **서버 배열 순서를 쓰지 않고** 정해진 축 순서(시선·표정·자세·손동작·목소리)로 다시 세운다(`GuestReview.orderedRatings`) — 지인을 바꿔가며 비교할 때 순서가 흔들리면 눈이 못 따라간다. 모르는 축 코드는 버린다(`AttitudeAxisKind`).

보고서 응답은 축 **코드와 1~4 단계만** 주고 표시 문구를 안 준다(게스트 제출측 `AttitudeAxis` 와 달리). 그래서 판정 문구·항목 이름·아이콘은 `GuestAttitudeCopy` 가 갖는다 — 시선·목소리는 제출 화면 확정 문구를 서술형으로 옮겼고 나머지 3축은 그쪽도 확정 대기라 잠정이다.

## 하이라이트 상세 시트

`ReportHighlightDetailFeature` — 화면이 아니라 대본 하이라이트를 탭하면 올라오는 바텀시트. 리포트 카드와 영상 플레이어 STT 오버레이 **양쪽이 같은 리듀서를 재사용**한다. 차이는 `[영상 보러가기]` 노출 여부 하나(`showsVideoJump`) — 재생할 영상이 없으면 숨긴다.

시트는 `HighlightContext` 로 **문장이 아니라 대본 전체**를 받는다. 강조 구간 앞뒤를 흐린 색으로 함께 보여줘야 문맥이 남는다 — 문장만 넘기면 그게 사라진다.

톤(잘함/개선)은 강조 색과 진단 카드 아이콘만 가른다. 구조는 같아서 화면을 두 벌로 나누지 않는다.

레포 최초의 `.sheet` 도입 지점이다(기존 사용처 0). 진단 제목(행동형 키워드)·다음 대비 질문은 서버 확장 대기 — **재료가 비면 그 줄·블록을 렌더하지 않는다**. 필드가 생기면 값만 흘려보내면 되고 코드 경로는 안 갈린다.

## 영상 플레이어

`ReportVideoPlayerFeature` — 리포트의 종속 화면. AVPlayer 는 State 에 두지 않고 View-local `@State` 로 소유한다(선례 `GuestVideoPlayerView`). 만료 판정은 플레이어 책임이 아니다 — 리포트가 `playableVideoURL` 에서 걸러 만료 시 진입 자체를 막는다.

**AVPlayer 는 뷰가, 재생 상태는 리듀서가** 갖는다. 컨트롤 자동 숨김·진행바 칸 채움·대본의 «현재 줄» 이 모두 재생 시각에 딸린 화면 상태라서다. 뷰로 내리는 이동 명령은 `seekToken`(단조 증가) + `seekTarget` 쌍 — 뷰가 토큰 변화만 보고 seek 해서, 같은 시각으로 두 번 이동해도 놓치지 않는다.

컨트롤(딤·재생 버튼·하단 바)은 무입력 3초 뒤 숨어 영상만 남는다. 단, **일시정지 중에는 숨기지 않는다** — 다시 재생할 버튼이 사라진다. 대본 오버레이를 켜 둔 동안도 하단 바가 대본의 일부라 유지한다.

시간축은 서버 대본 타임스탬프에서 온다([[api#Interview Report]]): 구간(`segments`)은 진행바 칸 = 이동 단위, 단어(`words`)는 계약만 열어 둔 상태다. `VideoTranscript` 가 카드별 구간을 시간축 하나로 펼친다 — 진행바는 질문 턴이 아니라 영상 시간을 보여줘야 해서 카드 경계를 넘겨 잇는다. 구간이 없으면 칸이 없어지지 않게 영상 전체를 한 칸으로 대체한다.

**좌우 화살표도 초가 아니라 칸 단위**로 움직인다(`userTappedPreviousChunk`/`userTappedNextChunk`, 2026-08-05 — 옛 ±10초 폐기). «구간 = 이동 단위» 를 컨트롤까지 밀어붙인 것 — 화살표가 초를 세면 이동 결과가 진행바 칸과 어긋나 어디로 갈지 미리 보이지 않는다. 마지막 칸에서 오른쪽은 무반응이다(영상 끝으로 튀면 재생이 끝나 버린다).

대본 오버레이의 하이라이트는 리포트 카드와 같은 `TranscriptText` 규약(`AttributedString.link` + `openURL`)으로 부분 탭을 받는다. 탭하면 영상을 멈추고 상세 시트를 올리고, 시트의 `[영상 보러가기]` 는 그 장면으로 이동해 재생을 재개한다 — 근거 시각을 모르면 처음부터다.

**좌상단 X 는 이탈이 아니라 «뒤로»** 다(Figma 에 버튼이 하나뿐). 리포트 이탈은 메인의 X 만 담당해서 플레이어는 `closeRequested` 를 갖지 않는다.

## 지인 피드백

`ReportPeerFeedbackFeature` — 메인의 `[지인에게 면접 영상 보내기]` 로 진입. 태도 항목 5종(시선·표정·자세·손동작·목소리)을 토글로 골라 공유 링크를 만드는 화면이다. 항목 이름·아이콘은 리포트 메인과 같은 `GuestAttitudeCopy` 표를 쓴다.

**평가 독립성**: 지인에게 넘기는 payload 는 영상과 질문 경계까지다. AI 피드백(하이라이트·진단·다음 대비)은 넘기지 않는다 — 지인 평가가 AI 평가에 오염되면 4.6 의 2축 비교가 무의미해진다. 그래서 이 화면이 서버로 보내는 것도 항목 코드뿐이다. 링크 생성 계약은 `DomainFeedbackShare`([[api#Feedback Share]]), 게스트 제출측은 [[feedback]].

**생성은 되돌릴 수 없다**: 항목은 생성 시점에 링크로 잠기고 면접당 활성 링크는 1개(409)다. 그래서 성공 직후 화면은 완료 모달의 «링크 복사하기» 하나로 좁아지고, 복사는 클립보드 + 시스템 공유 시트를 이어서 연다(붙여넣기·바로 보내기 겸용). 복사 후 메인 갱신 흐름은 스펙 대기다. 토큰 → 지인 URL 조립은 클라이언트 몫 — 도메인은 `hilit.my` 확정(2026-07-29), 경로 구조는 웹 게스트 페이지 스펙 대기라 `shareLink(token:)` 한 곳에 모아 뒀다.

- 항목을 서버로 보내는 순서는 `AttitudeAxisKind.allCases` 로 고정한다 — `Set` 순회 순서는 실행마다 달라서 게스트 화면의 항목 순서가 흔들린다.
- 항목 0개는 CTA `.disabled` 로 막는다(서버도 0개면 400). 다크 화면용 disabled 변형이 시안에 없어 라이트용 g50 바로 그려진다 — 시안 나오면 교체.
- 클립보드는 Feature 안의 `PasteboardClient` seam — 네트워크 Repository 가 아니라 기기 IO 라 Domain 모듈 근거가 없다. 두 번째 사용처가 생기면 `SharedCommon` 승격.
