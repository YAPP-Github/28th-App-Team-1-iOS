# 디자인 시스템 — 사고 사례

같은 실수를 두 번 하지 않으려고 남긴다. **규칙만 적지 말고 무엇이 어떻게 틀어졌는지**를 남긴다 — 이유를 모르면 다음 사람이 같은 판단을 반복한다.

**append-only.** 항상 파일 끝에 붙인다(`.gitattributes` 가 `merge=union` 이라 동시에 추가해도 충돌하지 않는다). 기존 항목은 고치지 않고, 뒤집힌 결론은 새 항목으로 적고 옛 항목에 «→ N번으로 갱신» 한 줄만 단다.

형식: `## N. 한 줄 제목` / 무엇이 틀렸나 / 왜 / 규칙.

---

## 1. 원본색 에셋에 `foregroundStyle` 을 걸어도 아무 일도 안 난다 (2026-07-26)

**무엇** — `OnboardingAnalysisView` 가 `Image.Ic.success` 에 `.foregroundStyle(Color.HilitGreen.g500)` 을 걸고 있었는데, `IcSuccess.imageset` 에 `template-rendering-intent` 가 없어 원본색으로 렌더됐다. 코드만 보면 초록으로 칠해질 것 같은데 실제론 무효인 줄이 남아 있었다.

**왜** — 에셋이 template 인지 원본색인지는 카탈로그 설정에 있고 호출부에서 안 보인다. 리뷰로 잡히지 않는 종류의 어긋남이다.

**규칙** — 색은 **에셋에 구워서** 쓰고 틴트하지 않는다. 색 변형이 필요하면 변형별 에셋을 따로 둔다(Figma 도 `default`/`dark`/`disabled` 를 따로 그린다). 토큰 주석에 원본색/template 여부를 명시한다.

## 2. SVG 라고 크기 하나로 돌려쓰면 안 된다 (2026-07-26)

**무엇** — 아이콘이 SVG 니까 24px 한 벌로 16px 자리도 덮을 수 있다고 판단했다가, 실제 path 를 재보고 뒤집혔다. `plus` 는 24px 판이 «글리프 20 / 막대 4», 16px 판이 «글리프 12 / 막대 2» — 24px 을 16 프레임에 넣으면 막대가 **33% 두꺼워진다.**

**왜** — 벡터는 해상도 문제만 해결한다. 크기별 획 두께 보정(optical sizing)은 디자이너가 다시 그린 결과라 스케일로 재현되지 않는다.

**규칙** — Figma 에 크기별 판이 따로 있으면 **쓰는 크기마다 에셋을 받는다.** 다만 안 쓰는 크기를 미리 받지는 않는다(번들·토큰 부풀림). 토큰 이름에 크기를 넣되 **그 패밀리에 크기가 하나뿐이면 생략**한다(`Left.default` vs `Cancel.dark24`).

## 3. 문서는 «주제»가 아니라 «경로»를 따라 고쳐야 한다 (2026-07-26)

**무엇** — 색 토큰을 Tuist 생성 접근자로 바꾸면서 `design.md`·`color.md` 는 고쳤는데 `lat.md/architecture.md` 가 옛 `Color.load` seam 을 그대로 들고 있었다. 주제가 «색»인 문서만 찾았기 때문.

**왜** — 심볼·파일 경로는 주제와 무관한 문서에도 인용된다(아키텍처 노트, 다른 스킬, 작업 문서).

**규칙** — 심볼·경로 이름을 바꿨으면 **옛 이름으로 `grep -rn --include="*.md"` 해서 걸리는 문서를 전부** 고친다. 직접 다룬 문서만이 아니다. 주제로 찾으면 반드시 샌다.

## 4. Figma 원본이 서로 안 맞을 때는 구현하고 기록한다 (2026-07-26)

**무엇** — 버튼 6종을 옮기다 시안 자체의 불일치를 3건 발견했다: `bottom/filled-2/gray` 라벨은 `b800` 인데 같은 회색 배경인 `2color` 왼쪽 라벨은 `g700` · `modal/dubble-button` 세로 padding 만 15(나머지 modal 은 16) · `Medium/black` 이 `status=outlined` 인데 테두리 없음.

**왜** — 시안은 사람이 그린 것이라 변형이 많아지면 서로 어긋난다. 코드에서 임의로 «맞춰» 버리면 디자이너는 영영 모르고, 나중에 시안을 고쳤을 때 코드와 또 갈라진다.

**규칙** — 임의 통일하지 말고 **시안대로 구현 + 문서에 «디자이너 확인 대기» 각주**를 남긴다. 오타가 명백한 경우(15↔16)만 고치되 `@ds` 태그로 원값을 보존한다.

## 5. Figma variant 축을 그대로 enum 으로 옮기면 안 된다 (2026-07-26)

**무엇** — 버튼 Figma 축이 `status` 에 `2button-1disabled`(상태), `color` 에 `default/pressed/disabled`(상태) + `gray/2color`(색)로 섞여 있었다. 그대로 옮기면 존재하지 않는 조합이 표현 가능해지고 상태를 손으로 넘기게 된다.

**왜** — Figma 축은 «화면에 늘어놓기 좋은 분류»지 «타입 설계»가 아니다. 특히 상태(pressed/disabled/selected)는 SwiftUI 가 이미 갖고 있다.

**규칙** — 축을 직교로 다시 자른다. 상태는 `ButtonStyle`(`configuration`·`isEnabled`)에, 화면 전체에 걸리는 것(light/dark 판)은 Environment 에, 슬롯·레이아웃을 갖는 것(2버튼)은 View 에 둔다. 남은 것만 enum 파라미터.
